# Публикация dikunova.art на Timeweb Cloud Apps

## Схема
```text
Браузер ─► dikunova.art / api.dikunova.art (:443, SSL Timeweb)
            │ :8082
            ▼
         edge (nginx, всегда онлайн, заглушка при 502/503/504)
            ├─ dikunova.art      → app:8080 (Node, сайт + серверные функции)
            └─ api.dikunova.art  → бэкенд (обход блокировок для браузера)
```
Сайт — это Node-сервер (страницы рендерятся на сервере), а не статика, поэтому `app` запускается через `node .output/server/index.mjs`.

## Порты: не менять на 3000

| Уровень | Значение |
| --- | --- |
| Посетители | HTTPS 443, сертификаты Timeweb |
| Внешний порт приложения в Timeweb | **8082**, сервис **edge** |
| Проброс Docker Compose | **8082:8080** |
| nginx внутри edge | **8080** |
| Node внутри app | **0.0.0.0:8080** |
| Адрес сайта для nginx | **app:8080** |

Порт 3000 из приложенной рекомендации — пример для другого приложения, не требование этого проекта. В панели Timeweb нужно выбрать опубликованный порт **8082**, а не внутренний порт **8080**. `app` не публикуется наружу. TLS завершается на Timeweb; внутри сети Docker используется HTTP.

## Шаги
1. Подключить репозиторий проекта (GitHub) в Timeweb Cloud Apps → тип **Docker Compose**.
2. Внешний порт → **8082** (сервис `edge`).
3. Переменные окружения — из `.env.timeweb.example`.
4. Домены в Timeweb: `dikunova.art`, `www.dikunova.art`, `api.dikunova.art` → одно приложение, SSL включить.
5. DNS у регистратора: A-записи `@`, `www`, `api` → IP приложения Timeweb.
6. Деплой.

Переменные `VITE_*` нужны **при сборке** (Compose передаёт их как build args). После изменения этих переменных необходима пересборка, простого перезапуска недостаточно. Серверные переменные передаются при запуске. Приватные ключи не добавлять в `VITE_*`.

Для входа и сброса пароля разрешённые адреса возврата службы авторизации должны включать `https://dikunova.art/admin` и `https://dikunova.art/reset-password`, а основной адрес сайта — `https://dikunova.art`. Это отдельная настройка размещения, она не меняется автоматически вместе с Docker Compose.

## Проверка
- `curl https://dikunova.art/__edge_health` → `ok`
- `curl -I https://api.dikunova.art/rest/v1/` → ожидается ответ службы API, обычно `401` без ключа; один код `401` ещё не подтверждает чтение данных.
- Открыть сайт, галерею, блог, форму «Узнать о покупке», подписку и `/admin`.
- Проверить `https://dikunova.art/sitemap.xml`: все адреса должны начинаться с `https://dikunova.art`.

Успех `/__edge_health` подтверждает только работу nginx, не сайта или базы данных. Доступ к панели Timeweb, её текущим портам, DNS и сертификатам из проекта отсутствует; завершённое размещение подтверждается проверками на новых доменах после переключения DNS.

## Вход в админку
Письма подтверждения и сброса пароля ведут на адрес сайта — после переезда входите на https://dikunova.art/admin.

## Режим обслуживания вручную
```bash
docker exec <edge> touch /etc/nginx/flags/maintenance.enabled   # включить
docker exec <edge> rm /etc/nginx/flags/maintenance.enabled      # выключить
```
